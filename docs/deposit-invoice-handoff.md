

### Three-event rate-limit investigation — D702950/D702951/D702952, ready for publication

- Read-only ledger tracing on 23 October confirmed the three reports are distinct. `D702950` Deposit event `420002` is held on an HTTP 429 before any writer execution or Xero invoice ID, so `INV-702950-D` was never created. `D702951` created `INV-702951-D`, but its Main writer `1530001` is `reconciliation_required` because the Xero Main Draft failed exact retained contact/line/account/total read-back; generic deduction correctly created no receipt or Main amendment. `D702952` created `INV-702952-D`, then generic deduction attempt `120001` held at its source-read stage on HTTP 429 before any deduction event, payload binding, writer execution or amendment. Existing open alerts retain these no-write outcomes.
- The generic deduction audit/terminal handling from the prior release remains unchanged. This follow-up removes remaining financial read pressure: strict cached Xero financial preflight reads, contact v2/legacy name-email lookups and contact read-backs now use a GET-only tenant-queued transport. It permits precisely one repeat only for a literal 429 with a numeric `Retry-After` of 0–5 seconds. It cannot accept callbacks, POST or PUT; missing, malformed or longer header values remain a no-write hold.
- Financial VTiger reads now share one short-lived authenticated GET-only session across each complete Main/Deposit/customer source preflight. This avoids repeated challenge/login bursts for sequential Deal, Quote, service, customer and metadata reads. Existing one-time transient GET recovery remains; a VTiger 429 is retried only once when it carries a literal numeric `Retry-After` of 0–5 seconds. Login POSTs are never retried.
- `financialDraftWriteAllowsTransientRetry` is now hard-disabled for every financial Draft POST/PUT, including automatic Deposit creation. A lost/gateway response requires reconciliation; it can never cause a blind second Xero financial write. Existing per-document idempotency, claims and Draft-only constraints are retained.
